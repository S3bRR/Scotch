# Build 15 validation

Local candidate, tested November 14, 2026 on Apple M5 Pro, macOS 27.2.1.
No existing user bottle was opened or modified by these probes.

## Windows 11 bottle creation

The reported warning was a failed optional core-font step, rather than failed
Windows 11 initialization. `WinetricksService.baseEnvironment` added the bundled
cabextract directory, then merged Wine's environment and replaced that PATH.
The helper was present in the DMG but unreachable from Winetricks.

The service now assembles the Wine environment before adding the helper path.
Terminal exports the same controlled Wine/wineserver and helper settings without
exporting unrelated inherited environment variables. A relocated app test uses
Finder's minimal system PATH, executes the real bundled cabextract, checks the
selected engine and compiles the generated Terminal command without opening a
Terminal window. The release verifier also executes its bundled extractor.

A full isolated Windows 11 bottle creation completed with no setup warning.
All ten core font families were checked on disk and in winetricks.log. The
existing Winetricks corefonts action also succeeded on the completed bottle.
The catalog and metadata retained Windows 11 and default Auto. An older bottle
missing fonts can use Winetricks → corefonts; it need not be recreated.

Evidence: `.build/windows11-corefonts-live15.log` and
`.build/bottle-creation-regressions15.log`. The live test copied the runtime into
`com.s3brr.Scotch.BottleCreationLiveProbe.21777C4C-61AB-44BD-BEFF-74025E933F6B`.
Only its own prefix processes were stopped afterwards.

## Main Backend Auto

Auto is the first option in the main Backend picker and is enabled for newly
created bottles. A separate saved policy keeps the actual installed renderer
available as the fallback/current backend. Auto remains selected after a launch
changes that renderer. Existing explicitly selected backends decode as manual.
The new bottle metadata schema is 1.2.0; future metadata remains protected.

Default application profiles inherit the bottle policy. Explicit per-program
Auto and manual overrides still work, with manual choices first. Confirmed
working application setups can also be reused through inherited Auto. Existing
availability checks, idle-process guards, full snapshots and launch lease
protection apply before a renderer transition.

Policy tests passed new defaults, serialization, legacy manual migration,
launch-time inheritance, retention of Auto after a renderer selection, explicit
manual bottle behavior and remembered application choices. Existing PE/parser,
profile preservation, missing-runtime, recovery and process-ownership checks
also passed. Desktop inspection of an isolated fixture showed the main Backend
card and picker selected Auto with DXVK shown as the current renderer.

Evidence: `.build/program-graphics-final15.log`. The final hardware run in
`.build/live-graphics-release15.log` exercises real OpenGL and DirectX 12 launches
using default program profiles inherited from the main bottle Auto policy.

## Regression and artifact checks

Update authentication, staged install/repair, replay/architecture rejection,
save/external-catalog preservation and snapshot/restore regressions passed in
`.build/update-verification-release15.log`. Steam argument separation, untouched
vendor updates and legacy-helper recovery passed in
`.build/steam-policy-release15.log`.

Native profile `scotch-graphics-2` is unchanged from build 14, including its
Steam child-surface/CEF loader fix and verified first-install/GPU tests. Its
archive SHA256 remains
`a458c9e3fb90eb0c7af67304657d69ab2c2e21e6ed0305378cc6f3a2b820c75f`.
The build 14 validation report retains the live fresh-Steam evidence and the
user's confirmation that its window renders.

The final local receipt `.release/build15/Validation.txt` is written after the
hardware run, DMG/source audit and signed app replacement/relaunch test. It
records their actual results, checksum and local candidate signatures. No
commits, pushes, tags, public releases or feed publication are performed.

Individual games and other Mac/macOS combinations still need manual testing.
Auto infers compatibility rather than benchmarking performance. Backend changes
remain bottle-wide and require idle Wine processes and a complete recovery
copy, including installed games. Quit Steam and Scotch before replacing the app;
retain Application Support and custom bottle folders.
