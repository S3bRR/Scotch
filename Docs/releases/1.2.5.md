## Scotch 1.2.5 (build 18)

### Bug fixes

- Changing graphics backends, switching Wine runtimes, and adopting the matched Wine engine no longer scan or copy the whole bottle. This fixes the false need to free another game's worth of disk space just to select D3DMetal. Wine must still be idle. Old snapshots are not deleted; swapping with one exchanges the directories without making another copy. Make your own backup before a risky Wine upgrade.
- The bottle Backend picker now defaults to **D3DMetal (DX11/12)** instead of Auto. Bottles previously set to Auto migrate to D3DMetal; explicit choices such as DXVK are preserved. Per-program Auto and manual overrides remain available. This corrects the default for DX12 games; it is not a guarantee of Diablo IV compatibility.

### Storage and packaging

- **Settings → Storage → Clear Download Cache** shows the size of downloaded runtime packages and removes only those packages. Installed games, bottles, saves, and runtimes remain intact. Repair may need to download packages again.
- Fresh or repaired Metal engines skip the upstream `include` directory (about 69 MiB for the pinned engine). Existing installations are not pruned on update.
- Finder thumbnails and Scotch share a small executable-icon reader. The thumbnail extension no longer links the full Wine runtime implementation. The app bundle omits development headers, unneeded updater architectures, and local symbols; Wine’s Intel components and the offline graphics payload remain included.

### Installation and source

Quit Scotch and replace the app in Applications; **do not uninstall**. Requires Apple Silicon, macOS 26 or later, and Rosetta. The default build is ad-hoc signed, not notarized. Verify the DMG against `Scotch.dmg.sha256`. Complete corresponding Scotch/Wine/Mesa source and license materials are provided separately as `ScotchGraphicsSources.tar.xz` with its checksum.
